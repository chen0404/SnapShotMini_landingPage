# SnapShotMini Landing Page Layout V1

狀態：已確認，待開發
確認日期：2026-07-30

## Design Read

這是一個以消費者情感吸引 B2B 店家的硬體 Landing Page，採 Nintendo 2001 的 Y2K 遊戲主機語言。

- 視覺變化：8
- 動態強度：6
- 資訊密度：5

## Landing Page Layout

### 導覽列

- SnapShotMini Logo
- 導覽項目：產品、拍貼流程、使用情境、FAQ
- 右側固定 CTA：`打造專屬拍貼`
- 使用碳黑材質與橘色操作鍵

### Hero 首屏

- 採左右不對稱分割版面
- 左側放置文案，右側展示 GPT Image 2 美化後的原型機
- 標題：`今天的我們，值得一張。`
- 副標：`店內限定相框，讓每次相聚都能立即拍下、印出、帶走。`
- 主要 CTA：`打造專屬拍貼`
- 次要 CTA：`看看怎麼運作`

### 產品展示

- 使用全寬商品照
- 忠於原型機結構，移除線材、污漬與辦公室背景
- 以主機銘牌形式呈現規格：
  - `30 × 30 × 30 cm`
  - `10 吋觸控螢幕`
  - `10 kg`
- 可切換白色原型與不同外觀皮膚

### 客製內容

- 標題：`從第一眼，到最後一張，都能是你的。`
- 不使用三張等寬功能卡
- 採不對稱排版展示：
  - S1 客製設備首頁
  - S2 多種相框版型
  - 實體列印成品

### 拍貼流程

- 標題：`從開始，到帶走。`
- 桌面版使用橫向捲動的主機操作軌道
- 依序展示：
  - 開始
  - 選相框
  - 付款
  - 拍照
  - 選照片
  - 列印與下載
- 付款畫面標示為只在付費販售情境出現
- 手機版改為垂直流程

### 使用情境

- 標題：`免費，因為好玩。付費，因為只有這裡有。`
- 左側展示品牌招待情境
- 右側展示創作者或門市限定相框的付費販售情境
- 使用真實情境影像，不使用通用圖示卡片

### FAQ

預計回答：

- 可客製哪些內容
- 免費與付費流程如何切換
- 支援哪些支付方式
- 設備需要多少空間
- 網路與電力需求
- 耗材與維護方式
- 導入所需時間

尚未確認的資料不得先行杜撰。

### 留單 CTA

- 使用碳黑大型控制面板
- 標題：`讓下一張，出現在你的店裡。`
- 說明由業務後續聯絡，並依品牌與場域討論客製內容
- 表單按鈕統一使用：`打造專屬拍貼`

### Footer

- SnapShotMini Logo
- 公司聯絡資訊
- 隱私權政策
- 不放假版本號或純裝飾資訊

## 視覺規則

- 冷色金屬機殼使用 Periwinkle 與 Chrome Indigo
- 碳黑區域只用於導航、控制與表單
- Signal Orange 只代表可點擊或前進
- 面板使用銳利切角與硬式斜面，不使用柔軟圓角卡片
- 標題使用厚重無襯線字，中文搭配 Noto Sans TC Black
- 預設為淺色金屬模式
- 深色模式整頁統一轉為深靛藍，不在頁面中間任意切換主題

## 動態規劃

- Hero 產品以輕微組裝落位方式進場
- 相框版型以實體照片堆疊方式切換
- 拍貼流程是唯一使用捲動敘事的區塊
- 按鈕具備實體按鍵下壓感
- 不使用無意義跑馬燈、發光特效或連續漂浮動畫
- 減少動態模式下全部改為靜態內容

## 圖像規劃

- Hero 以現有原型機照片為不可變的結構基準
- GPT Image 2 只負責美化材質、清理細節、置換背景與製作外觀皮膚
- 不擅自重新設計機身比例、螢幕、鏡頭或出紙口
- Hero 文案與 CTA 使用網頁文字，不直接烘焙進生成圖片

## 不採用項目

- 不公開價格、買斷、租賃或分潤方式
- 不使用虛構合作案例、客戶 Logo、評價或成效數字
- 不使用通用三卡功能區
- 不使用假產品 UI、裝飾性版本號或無意義技術標籤

## 正式開發前待確認

- 表單欄位與名單接收方式
- 實際支援的支付品牌
- 電力、網路、耗材、維護及導入時間
- 希望展示的外觀皮膚方向
- S1、S2、S4-S6 的高解析原始畫面
